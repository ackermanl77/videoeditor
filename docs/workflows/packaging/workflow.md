# Packaging a Standalone Build Workflow

## Goal

Package the app (with the Qt runtime) into a folder that runs with no Python installation required, and on Windows into a per-user installer for that folder.

## Steps

1. Create and activate a virtual environment with the Python in `.python-version` (3.14), then `pip install -r requirements.txt -r requirements-build.txt -c requirements-lock.txt` (`requirements-build.txt` adds PyInstaller; the lock file pins every transitive version, regenerated by `scripts/make_lock.py`).
2. *(Optional, recommended)* Download an FFmpeg build for the target OS and copy `ffmpeg`/`ffmpeg.exe` and `ffprobe`/`ffprobe.exe` into a `bin/` folder at the project root, next to `build.spec` — this bundles FFmpeg so end users don't need it installed separately. `build.spec` auto-detects any file in `bin/` whose name starts with `ffmpeg`/`ffprobe` and bundles it, no spec changes needed. Without this step, `core/ffmpeg_utils.py::find_binary()` falls back to the system `PATH`, then the `imageio-ffmpeg` package's bundled binary.

   **Use the "essentials" build, not "full."** On Windows, gyan.dev's own **full** build's `ffmpeg.exe`/`ffprobe.exe` are ~222MB *each* (statically links codecs/SDKs this app never uses — Decklink, fdk-aac, etc.), which would bloat `VideoEditor.exe` from ~60MB to 500MB+. The **essentials** build's binaries are ~98MB each — still statically linked with everything `CONTAINER_CODECS` actually needs (`libx264`, `libx265`, `libvpx`, `libopus`, `libmp3lame`) — for a ~135MB final exe. Confirmed both ways while bundling FFmpeg into a real release build: `curl -sIL https://www.gyan.dev/ffmpeg/builds/ffmpeg-release-essentials.zip` resolves to the correctly-sized essentials package; the plain, un-suffixed `ffmpeg-release-full.zip` on the same page is the one to avoid here.
   To get exactly the build the release uses, run `python scripts/fetch_ffmpeg.py`: it downloads the FFmpeg version pinned in `ffmpeg.lock` (URL, archive SHA256 and each binary's SHA256) and installs `ffmpeg.exe`/`ffprobe.exe` into `bin/`, failing on any hash mismatch. `release.yml` and CI's integration job use the same script.

   `build.spec` excludes `imageio_ffmpeg` whenever `bin/` holds FFmpeg (its own 87.6 MB `ffmpeg` was never used in the packaged app) and drops the Qt Quick/Qml/Pdf modules and DLLs (plus the `qpdf` image plugin): walking the PE import tables of every Qt module/plugin the app uses reaches none of them. `opengl32sw.dll` (Qt's software-OpenGL fallback) is excluded too: the preview's `QVideoWidget` renders through D3D11/raster, and in a built exe it was never loaded, neither at launch nor during QMediaPlayer playback (even with `QT_OPENGL=software`). Measured on a 2026-10-01 build (PySide6 6.11.2, FFmpeg 9.0.1 essentials): `dist/VideoEditor.exe` is 117.4 MB and unpacks 293 MB / 260 files per launch (163.5 MB / 435.5 MB before these exclusions); dropping `opengl32sw.dll` alone saved 7.6 MB / 20.6 MB.
3. Run `python build.py` (a thin wrapper around `pyinstaller build.spec`), or `python build.py --installer` to also compile `installer/VideoEditor.iss` with Inno Setup 6 (`ISCC.exe` on `PATH` or in its default install folder; the version comes from `core.__version__`). `build.py` stops when the interpreter isn't the `.python-version` one (`--any-python` overrides). Add `--sign` to Authenticode-sign `VideoEditor.exe` and, with `--installer`, the installer and its uninstaller (Inno Setup's SignTool, `#ifdef Sign` in the `.iss`), with signtool from the Windows SDK and the certificate whose SHA-1 thumbprint is in `VIDEO_EDITOR_SIGN_THUMBPRINT` or `CODESIGN_THUMBPRINT`, timestamped by `VIDEO_EDITOR_TIMESTAMP_URL`/`CODESIGN_TIMESTAMP_URL` (default DigiCert).
4. The output is the `dist/VideoEditor/` folder: `VideoEditor.exe` (no extension on macOS/Linux) plus `_internal/`, which holds Python, Qt and the bundled FFmpeg. Ship the whole folder. `--installer` adds `dist/installer/VideoEditor-<version>-setup.exe`: a per-user install (`PrivilegesRequired=lowest`, every registry entry under HKCU) into `%LOCALAPPDATA%\Programs\OpenVideoEditor`, with a Start menu entry, an optional desktop shortcut, an uninstaller, and the `.vproj` association (`OpenVideoEditor.Project`; `main.py` opens a `.vproj` given as its argument). An upgrade deletes the old `_internal\` first, so no stale files survive.

   This used to be a one-file exe, which unpacked ~293 MB (205 MB of it FFmpeg) into `%TEMP%\_MEI*` on every launch, took seconds to do so, and left the folder behind whenever the app was killed. Measured on the first onedir build (2026-10-02, PySide6 6.11.2, PyInstaller 6.22.3, FFmpeg 9.0.1 essentials): 296 MB in 261 files, `--self-test` passes, and `VideoEditor.exe "<project>.vproj"` shows the window with that project loaded after 2.2 s (the one-file exe took 3.5–3.8 s to show an empty window), with nothing written to `%TEMP%`. The installer was later compiled locally and checked with a silent install and uninstall (2026-10-02): the uninstall now also deletes the `.vproj` and `.vproj\OpenWithProgids` keys when they are left empty. An interactive install (Start menu entry, double-clicking a `.vproj`) has not been tried yet, and `release.yml` (which also compiles the installer) has not run since the switch to the folder build.

## Cross-compilation

PyInstaller does not cross-compile — build on the same OS you're targeting (Windows for `.exe`, macOS for a macOS app, etc.).

## Where the bundle is found at runtime

`core/ffmpeg_utils.py::_bundle_dir()` uses `sys._MEIPASS` (the `_internal/` folder of the onedir build) to locate a bundled `ffmpeg`/`ffprobe` next to the running executable or in its `bin/` subfolder, before falling back to `PATH`. `main.py` shows a non-fatal warning dialog if FFmpeg can't be found by any of those routes, since media import, thumbnails, preview, and export all depend on it.

## Validation

`tests/test_packaging.py` checks the build *configuration* (the spec builds a folder, the installer packages that folder per user and registers `.vproj`, `build.py`/`release.yml` use both, `main.py` opens a `.vproj` argument), and `release.yml` runs `--self-test` on the built exe, but nothing automated launches the GUI of a packaged build. Verify manually after each `python build.py`: launch the produced executable on a clean machine/VM without the dev virtual environment active, confirm the splash screen and taskbar icon appear, and exercise the FFmpeg-dependent path (import a file, play it, export a short clip) — with and without a bundled `bin/ffmpeg.exe` present, to confirm both the bundled-binary and system-`PATH` lookup paths work.

Confirming *what actually got bundled* doesn't need a second machine, and catches a stale/wrong build before ever launching the exe: with the onedir build the binaries are plain files (`dist/VideoEditor/_internal/ffmpeg.exe`, `ffprobe.exe`), and the Python modules sit in `_internal/base_library.zip` and the `PYZ` archive inside `VideoEditor.exe`, which `PyInstaller.archive.readers.CArchiveReader`/`ZlibArchiveReader` can open — useful for confirming a specific *source-code* change actually made it into the build (not just an old cached copy under `build/`), extracting a module's compiled bytecode out of the `PYZ.pyz` entry and checking its `co_consts` for a string that only exists in the new code — this is how the Shorts-export UI strings were confirmed present after a rebuild, and how a stale pre-Shorts `dist/VideoEditor.exe` (whose timestamp predated every commit in the repo) was caught in the first place. Also always sanity-check the bundled `ffmpeg.exe`/`ffprobe.exe` themselves still run standalone (`bin/ffmpeg.exe -version`) before packaging — a build that embeds a corrupted or partially-downloaded binary would otherwise only surface as an export failure deep inside the packaged app.

## Version, self-test and UPX (P2)

- `core/__init__.py: __version__` is the single version source: `build.spec` renders the exe's Windows version resource from it (`scripts/version_info.py`, `version_info.txt` is the template), the About box and `.vproj` files show it, and `release.yml` fails when the pushed tag isn't `v<__version__>`.
- `VideoEditor.exe --self-test` (or `python main.py --self-test`) runs before any `QApplication`: version, FFmpeg/FFprobe paths and versions, NVENC, the video-decoding setting, 25 required filters (including vid.stab, reverse/areverse/tpad), and a real one-second export checked with ffprobe; exit code 0/1, report also in `%TEMP%\VideoEditor-selftest.txt` (the exe has no console). `release.yml` runs it on the built exe before publishing.
- `upx=False` is explicit. `docs/USER_GUIDE.md` is bundled for **Help > User Guide**.
- FFmpeg is still the static "essentials" build; a shared-library FFmpeg (K3) would avoid linking the codecs into both ffmpeg.exe and ffprobe.exe.
